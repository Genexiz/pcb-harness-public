# M4 exact support qualification

The support producer selects purchasing parts for every support instance and captures source bytes, pin semantics, package geometry and calculations. Every purchasing row is checked against the qualified instance reference, part ID, MPN, value, procurement type and block; accessories must match the catalog exactly. It grants no human confirmation or layout authorization. The qualified topology remains a candidate for independent circuit review. Source PDFs remain in ignored `runs/m4/support-qualification-2026-10-10/sources`, because no redistribution license was inferred.

## Integration and reproduction

`pcb_harness.orchestration.support_qualification.qualify_support(topology, repository_root)` returns a new topology, exact support BOM, catalog, checklist delta, firmware requirements and engineering analysis. The input object is untouched. Core part choices and interfaces are retained; only MCU OSCOUT and external MCP crystal OSCOUT become NC. Source completion can independently select MAX3232IDWR. Parent SDO semantic models and power annotations are retained.

`capture_support(topology, repository_root, output)` creates a repository-shaped source subset with `base-topology.json`, `qualified-topology.json` and integrity hashes. `verify_support(output)` hashes the frozen files and recomputes the result. `support_asset_bytes(repository_root_or_packet)` returns a library overlay keyed by `symbols/...` and `footprints/...`. Apply this overlay while freezing the parent circuit's library input. Each support symbol is a single unit with source-reviewed pin numbers, so no unused gate unit can silently disappear. The parent should admit `source_reviewed` support status only with the captured packet verified. The checklist delta supplies corrected required references, values, complete NC sets and corrected pin nets; it is a concrete input for independent source review, not proof of human review.

The RPW0010A footprint is authored from TI's recommended layout on source PDF page 73. It has compound outer contacts, two 0.30 × 2.40 mm power lands, and ten logical pin numbers. It has no conventional exposed pad. FTSH-105-01-L-DV-K is SMT, not through-hole: its source land pattern uses 6.86 mm outside and 2.79 mm inside span, 0.74 mm pad height and 1.27 mm pitch. Contact 7 is physically omitted for keyed SWD. Original KiCad footprints are frozen with their hashes; attribution remains subject to the parent library/license review. New schematic positions are snapped to 1.27 mm and remain serialization positions, not board placement.

## Electrical corrections

- USB4105-GF-A replaces an unsourced connector. PESD2USB5UX-T,215 has two line pins and a grounded common anode; it removes the previous ESD steering rail to USB VBUS. TMUX1574PWR disconnects D+/D− when `VBUS_PRESENT_N` is high. SEL is grounded; unused channels are grounded. The 1.5 kΩ D+ pullup stays on the isolated MCU side, powered from 3V3. Q2 is removed, so its body diode cannot feed the host-side data lines. R11 pulls EN high whenever VBUS is absent and the board is powered. At VDD=0, the switch specifies isolation for signals through 3.6 V, with ±2 µA maximum powered-off leakage; this is bounded isolation rather than zero leakage. Source RON maximum is 4.5 Ω and CON maximum 12 pF. USB full-speed edge/ringing/capacitance still requires layout validation.
- SN74LVC1G125DBVR puts external MISO behind a three-state output with OE tied to the **internal** external-device CS; R26 pulls CS high at reset. Thus an external slave cannot drive the shared MISO while a CAN controller is selected. SN74LVC125APWR buffers outgoing SPI and UART lines; UART RX is independently buffered. Ioff supplies board-off protection. TCA9511ADR supplies powered-off high-impedance I²C lines. Headers accept qualified 3.3 V devices with a common ground; this is not a 12/24 V industrial GPIO input design.
- The shared external supply is limited by TPS2553DBVR with ILIM shorted to IN: the source specifies 50–100 mA. The two headers share this allocation. Reverse-voltage response is 3–7 ms, so externally injecting power into the header supply remains outside the declared envelope.
- WIZ550io gets a separate TPS259470ARPWR with RILM=6.65 kΩ, true reverse blocking and a controlled supply ramp. U17/U18 isolate all module host inputs and module outputs; module pullups are referred to ETH_3V3. This prevents host signal pullups from bypassing the module limiter when the module supply is faulted or off.
- Main regulated 5.0 V ±2% passes through TPS259470ARPWR with 3.32 kΩ ILM. Precision TNPW0805 383 kΩ/150 kΩ UVLO and 510 kΩ/150 kΩ OVLO dividers meet the source's ≥350 kΩ reverse-polarity pin-current recommendation. The calculation includes 0.1 µA input leakage and a 0.25% resistor model covering initial tolerance, 0–50°C TCR and drift. UVLO rising thresholds are 4.150–4.400 V; OVLO rising thresholds are 5.134–5.453 V. No USB-only mode, PoE or 12/24 V operation is claimed. Fast OVLO response and current limiting do not establish system surge certification.
- 120 Ω CRCW1206120RFKEAHP terminations and removable Samtec shunts replace generic resistor/jumper purchasing choices. RS-485 optional 330 Ω bias networks are independently selectable; both bias shunts are removed by default. Worst modeled differential bias with two 120 Ω terminations is 0.2565 V. Only one bias point is enabled on a physical bus. Transceiver built-in fail-safe behavior does not remove the requested selectable bias feature.

## Clocks and passives

Y1 is ASE-8.000MHZ-L-C-T and Y2/Y3 are ASE-20.000MHZ-L-C-T. Pins are EN=1, GND=2, OUT=3, VDD=4. EN is tied to 3V3. All passive-crystal capacitors are removed; each oscillator gets local decoupling. STM32 uses HSE bypass, while external MCP controllers use 20 MHz digital clock without PLL. The selected ASE source specifies 7 mA maximum each, 45–55% duty, 4 ns maximum rise/fall, 2 ms maximum startup, 15 pF output load, and ±50 ppm overall stability. Allowing first-year aging gives a conservative ±53 ppm clock model. MCU PLL6 produces 48 MHz nominal (48.002544 MHz modeled high); USB clock tolerance is reviewed by the parent. MCP SYSCLK is at most 20.00106 MHz, within its 2–40 MHz external-clock range. A 40 MHz positive-tolerance oscillator was deliberately avoided.

L1 is XAL4030-332MEC, 3.3 µH ±20%, following TPS6216x's low-input-voltage full-current recommendation. Its source specifies 28.6 mΩ maximum DCR at 25°C; 5.9 A saturation and 5 A at 20°C rise are characterized typical values and remain labeled as such.

TDK exact 50 V 100 nF, 16 V 1 µF/4.7 µF, 25 V 10 µF and 16 V 22 µF parts replace size-only capacitor types. C25–C28 use 100 nF 50 V C0G **1206** C3216C0G1H104J160AA so negative charge-pump bias and DC-bias capacitance loss are accounted for. C30 changes to the source-qualified 1210 10 µF. Capacitor DC-bias plots were visually inspected. The X7R sheet is characterization, not a guaranteed minimum: engineering-analysis.json explicitly combines 10% bias loss, 10% initial tolerance, 15% temperature allowance and 2.5% aging. This yields 6.713 µF modeled input and 14.769 µF modeled output effective capacitance. The regulator recommends nominal 10/22 µF ceramics; actual loop/transient behavior is part of subsequent board validation. The C0G pump model remains 94.525 nF with 5% initial tolerance and 0.5% bias allowance.

## Bounds and remaining proof

WIZ550io's published 141 mA is typical. It is not promoted to a maximum. The datasheet current-limit table specifies 425–575 mA before resistor tolerance **at its default VIN=12 V test condition**, giving 420.79–580.81 mA modeled design bounds. The WIZ branch uses 3.3 V and main input uses 5 V. Both are inside the operating voltage range, but the table does not explicitly guarantee these limits across that range; the packet records the test voltage and `guaranteed_at_selected_voltage=false` for both branches. Qualification at selected rails requires vendor evidence or board measurement. RON separately has an explicit 2.7–23 V condition, so it is not subject to this same extrapolation. Main output and shared header currents can therefore be budgeted without inventing the module maximum. Including the regulator power-save -3.5% voltage bound, 45 mΩ switch resistance and an additional conservative 16.9 mV forward-regulation allowance gives 3.14146 V at the module. The frozen WIZ550io online manual (SHA256 9869c0e996064e670c65fbd7cefaf9f921e3b35312b105f8370e3e66139c1297, Electrical Characteristics / DC Characteristics / VDD row) actually specifies 2.97–3.63 V, a ±10% range. The earlier 3.135 V statement was a stricter ±5% engineering target, not the module manufacturer minimum. The manufacturer static margin is therefore 171.46 mV; the stricter engineering target has 6.46 mV margin. Parent analysis still includes rail transient/ripple before accepting operation. Full-load PWM has 187.96 mV manufacturer margin. The module-side input buffers are inside the limited branch. The limiter's quiescent current is drawn upstream and belongs in the regulator's load budget. Faulted current limiting intentionally permits lost Ethernet function; it does not prove fault-free nine-interface concurrency.

At the branch upper bound, switch loss is 15.18 mW and JEDEC 74.5°C/W gives 1.13°C modeled rise. TPS62162 thermal analysis uses a clearly declared 80% efficiency assumption and 1.5 × JEDEC 61.8°C/W for layout margin. At 0.85 A output and 50°C ambient the conditional model yields 115.01°C versus 125°C allowed. Efficiency is **not** guaranteed by the datasheet at the exact 5 V operating point, and JEDEC θJA is not an actual PCB measurement. Copper/thermal vias, input and output capacitor placement, load/rail transients and actual efficiency remain explicit validation requirements. These model limits do not become manufacturer guarantees.

The remaining indispensable evidence is concrete: current-limit behavior at actual 3.3 V/5 V rails and module startup/full-traffic current below the minimum qualified threshold over declared conditions, sufficient transient rail margin, ≤15 pF clock load, regulator effective capacitance/control-loop response, and actual board thermal behavior. The parent distinguishes an accepted static engineering model for M4 from physical M5/hardware acceptance.
