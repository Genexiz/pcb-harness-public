# M1 Kernel Execution Plan

> Execute inline with superpowers:executing-plans. This milestone uses the M0 contracts observed on KiCad 10.0.0; continuation validates KiCad 10.0.6.

**Goal:** structured query/action Kernel with revisions, locks, atomic mutation validation, rollback and action evidence. Memory backend supports behavioral tests; IPC backend supports real scratch runs. Neither backend grants fabrication release.

**Spec:** ../../PCB Harness — Design Spec (v2).md

**Architecture:** Kernel validates intent and expected revision, invokes one explicit backend mutation and computes violation deltas. Backend owns native commit/save/revert mechanics. KiCad staging is not visible through queries: validation happens after publish on the isolated scratch project, with guarded restoration if validation rejects the action.

**Stack:** Python 3.11, kicad-python 0.8.0, kicad-cli 10.0.6, pytest; no LLM calls or new external accounts.

## Constraints and review focus

- No autorouter/search/automatic shove; all action coordinates and layers come from the caller.
- Fresh revision and footprint lock checks happen before mutation.
- Native flip is gated to KiCad 10.0.6+ within the tested 10.0 family; older/future majors stay unsupported. Never emulate a flip by editing only the layer.
- Unknown/failed verification is never accepted as a clean action; rollback or explicit recovery-required state.
- Known temporary connectivity findings are reported separately from geometric regressions.
- Saving checkpoints must not erase unrelated live changes; conflict stops recovery with evidence.
- Memory checks are a limited test model and never substitute for KiCad release verification.

## Tasks and files

1. **Domain/action contracts:** `src/pcb_harness/{__init__,contracts}.py`; test finite mm geometry, typed errors, explicit polyline intents, revision/lock/unknown-net validation.
2. **Kernel + memory fixture:** `src/pcb_harness/{kernel,memory}.py`; tests use actual in-memory state to prove stale revision rejection, lock handling, geometry delta, strict rollback, permissive reporting, partial connectivity and action IDs. Memory only models segments/pad points on supported layers, not arbitrary footprints/DRC.
3. **IPC adapter:** `src/pcb_harness/ipc.py`; exact scratch identity, full state digest, expected revision before mutation, publish-before-query, guarded rollback, locks and capability checks, run artifact logging. Reuse fail-closed CLI reader from M0 with its regression suite; do not duplicate rule enforcement assumptions.
4. **Executable scratch smoke:** `experiments/kicad-ipc/kernel_smoke.py`; query→place→rollback/recover→route→verify with explicit paths. Known short must be rejected and restored. GUI-dependent cases remain unverified until executed; current M0 native probes already prove primitive operations.
5. **Review/verification/docs:** whole suite; one read-only review; fix Important findings with regression tests. Update capability report and ledger; commit without pushing/merging.

## Behavioral test order

- Write Kernel tests first and run RED (module/action behavior absent).
- Implement contract and Memory backend; run GREEN and inspect full suite.
- Write adapter identity/capability/recovery tests before implementing new helper logic.
- Run native scratch smoke and inspect native DRC/ERC/parity evidence. Preserve immutable source fixture and separate live project.

## Acceptance

Kernel rejects stale/locked/invalid intents before edits; strict new geometric violations restore baseline; permissive commits return actual deltas; temporary unrouted state does not make geometry-only checks pretend to be release validation; repeated action IDs cannot apply twice; any unknown recovery state stops further writes. Native scratch run proves integration before declaring the real backend verified. Full manufacturing profiles, all shape types and production multi-writer recovery remain explicitly gated beyond this initial Kernel slice.
